# Live 图带货资料库设计

## 目标

创建一个供个人使用的 Live 图带货资料管理网页，帮助用户按商品整理多套样品方案，并长期保存图片、文案、标题、BGM 和挂车标题等资料。

首版以电脑端 Chrome 为主要运行环境。资料直接保存到用户授权的电脑本地文件夹，不依赖公司服务器、云数据库或账号系统。手机端仅支持手动选择备份文件并进入只读查看模式，不保存修改，也不提供自动同步。

## 用户与使用范围

- 仅供一名用户使用。
- 主要在电脑端 Chrome 浏览器中录入、编辑和管理资料。
- 网页代码继续部署在 Cloudflare Pages，通过 HTTPS 地址访问。
- Cloudflare Pages 只托管网页代码，不保存用户录入的商品资料或图片。
- 首版不包含账号登录、云数据库、多人协作和自动跨设备同步。

## 信息架构

系统包含商品、样品方案和样式库三类核心数据。

### 商品

每个商品包含：

- 唯一标识
- 商品名称（必填）
- 商品链接（选填，填写时必须是有效的 HTTP 或 HTTPS 地址）
- 创建时间
- 更新时间

一个商品可以关联多套样品方案。删除商品时，同时删除该商品下的全部方案和图片；执行前必须明确提示影响范围并要求二次确认。

### 样品方案

每套样品方案属于一个商品，包含：

- 唯一标识
- 样式标识
- 多张样品图片
- 样品文案
- 样品标题
- BGM 名称
- 样品挂车标题
- 创建时间
- 更新时间

图片支持批量添加、缩略图预览、顺序调整和单张删除。图片保存前自动转换或压缩为适合网页使用的格式，在尽量保持可读性的同时控制磁盘占用。

### 样式库

样式是由用户维护的固定选项。用户可以新增和重命名样式。已被样品方案引用的样式不能直接删除；用户需要先为相关方案更换样式，或在删除操作中明确选择替代样式。

## 本地文件存储

### 文件夹结构

用户第一次使用时点击“选择资料库文件夹”，并通过 Chrome 授权网页读写该文件夹。推荐结构如下：

```text
Live带货资料库/
├─ library.json
├─ images/
│  └─ 商品ID/
│     └─ 方案ID/
│        ├─ 图片ID-1.webp
│        └─ 图片ID-2.webp
└─ backups/
```

`library.json` 保存商品、方案、样式、图片相对路径、数据版本和更新时间。图片文件保存到 `images` 下对应的商品和方案目录。`backups` 用于存放用户主动生成的备份。

### 浏览器权限

- 文件夹访问依赖 Chrome 的 File System Access API，并要求网页运行在 HTTPS 安全环境中。
- 网页不能在未授权的情况下访问电脑文件；文件夹必须由用户主动选择。
- 浏览器可在 IndexedDB 中保存文件夹句柄和少量界面偏好，但业务数据与图片不以 IndexedDB 为主存储。
- 再次打开网页时，若浏览器未保留权限，页面提示用户重新授权原资料库文件夹。
- 不支持文件夹访问能力的浏览器显示清晰说明，不允许用户误以为资料已经保存。

### 写入策略

所有编辑先在内存中完成校验，再写入图片文件和 `library.json`。数据文件包含格式版本号，方便未来升级。写入失败时保留当前页面内容，显示失败原因并允许重试，不用空数据覆盖原文件。

## 备份与设备迁移

- 用户可以复制整个资料库文件夹完成完整备份和迁移。
- 网页提供“导出备份”功能，把 `library.json` 和关联图片整理为一个扩展名为 `.livebackup.zip` 的可导入压缩文件。压缩包内部保留 `library.json` 和 `images` 目录结构。
- 导入前校验文件格式、版本和必要字段。校验失败时不修改当前资料。
- 导入支持“合并”和“覆盖”两种模式。
- 合并模式按内部唯一标识去重；发生冲突时保留更新时间较新的记录，并向用户展示合并结果。
- 覆盖模式会清空当前资料库并导入备份，执行前必须二次确认。
- 手机端每次通过文件选择器打开备份文件，以只读模式搜索和查看商品、方案与图片；手机端不允许编辑，也不把解压后的资料长期写入浏览器数据库。

## 页面与交互设计

### 整体布局

采用“商品卡片工作台”结构：

- 电脑端使用左侧导航和商品卡片网格。
- 手机端使用顶部导航和单列商品卡片。
- 视觉风格采用清爽蓝：白色背景、蓝色主操作、轻量阴影和清晰的信息层级。

导航包含：

- 全部商品
- 样式管理
- 备份与恢复

### 商品工作台

工作台顶部包含关键词搜索、样式筛选和“新建商品”按钮。关键词搜索覆盖商品名称、样品标题和样品文案；样式筛选显示包含该样式方案的商品。

商品卡片显示商品名称、代表图片、方案数量、包含的样式和最近更新时间。点击卡片进入商品详情。

### 商品详情

商品详情展示商品名称、商品链接及其全部样品方案。用户可以：

- 新增方案
- 编辑方案
- 复制方案
- 删除方案
- 打开商品链接

每套方案以图片卡片展示主要图片、样式、样品标题和 BGM 名称。长文案在详情中完整展示，不在卡片上强行铺开。

### 编辑页面

新增和编辑方案使用独立页面，不使用尺寸受限的弹窗。页面包含图片区、样式选择、文案、标题、BGM 名称和挂车标题。离开存在未保存修改的页面时必须提示用户。

### 样式管理

样式管理页以列表形式展示样式名称和引用数量，提供新增、重命名和删除操作。删除受引用样式时，页面要求用户选择替代样式或取消操作。

### 备份与恢复

备份页展示当前资料库文件夹状态、最后写入时间和备份操作。导入时先显示备份摘要，包括商品数、方案数、图片数和导出时间，再让用户选择合并或覆盖。

## 搜索与筛选

- 搜索不区分英文字母大小写。
- 搜索商品名称、样品标题和样品文案。
- 搜索词为空时显示全部商品。
- 样式筛选可与关键词搜索组合使用。
- 默认按最近更新时间倒序排列商品。
- 无结果时显示清晰的空状态，并提供清除筛选入口。

## 校验与错误处理

- 商品名称必填并去除首尾空格。
- 商品链接为空时允许保存；非空时必须通过 HTTP/HTTPS 地址校验。
- 样品方案必须选择一个有效样式。
- 图片仅接受浏览器可读取的常见图片格式；单个异常文件不阻止其他有效图片加入，但必须指出失败文件。
- 删除商品、方案、图片和覆盖导入均需要二次确认。
- 文件夹权限失效时停止写入并请求重新授权。
- 读取到损坏或不兼容的 `library.json` 时进入保护状态，不覆盖原文件，并提示用户从备份恢复。
- 图片文件缺失时保留方案文字数据，显示缺图占位和文件路径诊断信息。

## 技术架构

首版采用 React、TypeScript 和 Vite 构建纯前端应用，不引入后端。使用浏览器原生 File System Access API 管理电脑本地资料库，使用 `fflate` 生成和读取 `.livebackup.zip` 备份。代码按职责拆分：

- 应用入口与路由：管理工作台、商品详情、编辑、样式和备份页面。
- 数据模型：定义商品、方案、样式、图片和备份格式。
- 本地文件存储：封装目录授权、JSON 读写、图片写入与删除。
- 查询服务：负责关键词搜索、样式筛选和排序。
- 图片处理：负责预览、压缩、格式转换和排序。
- 备份服务：负责导出、校验、合并和覆盖恢复。
- UI 组件：商品卡片、方案卡片、表单、确认提示和空状态。

应用采用客户端路由。页面状态与表单状态由 React 管理；业务实体读写必须通过本地文件存储服务，不允许 UI 组件直接操作文件句柄。构建产物继续发布到 Cloudflare Pages，并保持“无后端、本地文件夹主存储”的边界。

## 测试与验收

### 自动测试

- 商品、方案和样式的新增、读取、编辑与删除。
- 被引用样式的删除限制与替换流程。
- 关键词搜索、样式筛选、组合查询和更新时间排序。
- 商品链接和必填字段校验。
- 图片顺序变更、异常图片处理和缺图状态。
- `library.json` 的序列化与反序列化一致性。
- 备份导出后重新导入的数据与图片一致性。
- 合并冲突、覆盖恢复、损坏文件和版本不兼容处理。

### 浏览器验收

- 电脑端 Chrome 可以授权文件夹、创建资料并在刷新后重新读取。
- 商品可以包含多套方案，每套方案可以保存并排序多张图片。
- 搜索和样式筛选结果正确。
- 关闭并重新打开页面后，本地文件夹中的资料仍然存在。
- 取消授权或移除文件后，页面给出明确且安全的错误提示。
- 电脑尺寸下所有管理功能完整可操作；手机尺寸下可以导入备份、搜索和只读查看资料，且无横向滚动。
- Cloudflare Pages 公网 HTTPS 地址可以加载应用代码，但不会把业务资料上传到 Cloudflare。

## 首版不实现

- 用户账号和权限系统
- 云数据库和云端图片存储
- 自动跨设备同步
- 多人协作
- BGM 音频文件上传或播放
- 数据分析、销量跟踪和自动采集商品信息
